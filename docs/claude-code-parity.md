# Pi Desktop 面向个人用户的能力评估

> 更新日期：2026-11-19
> 对比对象：Pi Desktop 当前工作树与 Claude Code 2.1.280 的本地开发体验
> 评估对象：需要在自己的电脑上完成编码、调试、审查和小规模自动化的个人开发者

## 0. 结论

Pi Desktop 当前已经适合个人用户的日常本地开发。文件读写、命令执行、交互终端、Git 差异、检查点、项目记忆、Plan、Hooks、Skills、自定义 Agent、MCP、后台任务、Worktree、Teams、Workflow、Cron、Monitor、Todo 和本机外部 Agent 均已具备对应实现或界面入口。

按照个人用户的使用频率重新加权后，当前完成度约为 **4.1 / 5，约 82%**。这个分数用于安排开发顺序，不表示模型效果或 Claude Code 的官方兼容率。

当前最值得投入的能力集中在日常可靠性和低摩擦使用体验。

1. 长任务在应用退出后可以继续接管，保留活动任务的进程和审批状态。
2. 把沙箱范围、交互终端、MCP 和外部 Agent 的权限边界显示得更清楚，并逐步扩大可保护范围。
3. 提供模型故障转移、连接诊断和更顺畅的首次登录流程。
4. 直接兼容常见的 Claude MCP 配置，减少个人项目迁移成本。
5. 继续完善搜索、快捷键、草稿保存和本地质量检查。

企业 SSO、组织审计、托管策略、云会话、手机接管、Remote Control、插件市场和 Chrome 操控不影响个人用户的核心闭环。它们保留为远期选项，当前不进入个人版主路线图。

## 1. 评估范围与方法

### 1.1 个人用户画像

本报告按以下使用方式评估产品。

- 在 macOS 本地打开多个 Git 项目，使用一个或多个模型完成编码任务。
- 需要查看和修改文件，运行测试和脚本，审查 Diff，并在出错时恢复。
- 偶尔使用只读探索、Plan、后台子 Agent、Worktree 和本机 Codex 或 Claude Code。
- 维护少量个人规则、Skills、Hooks 和 MCP 服务。
- 关注密钥保护、误改文件、上下文失控、任务中断和成本可见性。

个人用户通常不需要组织级策略、跨设备会话、统一身份管理或大规模团队编排。评估将这些能力放在低权重中，避免它们拉低本地工作流的判断。

### 1.2 评分维度

| 维度 | 权重 | 个人用户关心的结果 |
| --- | ---: | --- |
| 本地编码闭环 | 30% | 读写、命令、终端、Git、Diff、检查点、测试和预览能否连贯完成 |
| 安全与恢复 | 20% | 权限、信任、沙箱、误操作恢复、进程和任务状态是否可控 |
| 上下文与规则 | 15% | 记忆、规则、压缩、Skills、Hooks 和项目配置是否稳定可复用 |
| 模型与 Agent | 15% | 多模型、连接管理、子 Agent、Worktree 和外部执行器是否好用 |
| 界面效率 | 10% | 搜索、快捷键、草稿、通知、面板和中文交互是否降低操作成本 |
| 安装与稳定性 | 10% | 构建、打包、升级、跨重启恢复和故障诊断是否可靠 |

5 分表示个人用户可以把它当作稳定主工具使用。4 分表示核心流程完整，少数边界需要手动处理。3 分表示能用但经常需要离开客户端。2 分表示只有原型或局部能力。1 分表示当前没有可用入口。

### 1.3 当前验证

- `npm run check` 通过。
- `npm run build` 通过。
- 在允许本地 loopback 服务和子进程的环境中，`npm run test:backend` 通过。
- `npm run verify:client` 已覆盖模型控制、工具审批、流式恢复、真实读写和 Bash、Git、PTY、后台任务、Worktree、Hooks、Skills、Rules、MCP、Plan、外部执行器、Teams、Workflow 和 `/batch` 等界面流程。
- 真实第三方账号、真实 OAuth 服务、Windows 实机和 Linux 实机仍需要单独验收。

## 3. 已经满足个人日常工作的能力

### 3.1 编码与终端

| 场景 | 当前能力 | 个人结论 |
| --- | --- | --- |
| 文件理解和修改 | `read`、`grep`、`find`、`ls`、`edit`、`write`、NotebookEdit | 满足日常编码和 Notebook 修改 |
| 命令执行 | Bash、单次命令、交互式 PTY、Ctrl-C、输出回放 | 满足测试、构建、调试和开发服务器场景 |
| 网页和预览 | WebFetch、localhost 预览和浏览器检查 | 足够应对本地 Web 开发，研究型搜索仍需外部浏览器 |
| 代码智能 | 语言服务器诊断、符号和定义跳转 | 已达到个人项目的基础需求，依赖本机语言服务器 |
| 结构化提问 | AskUserQuestion 多选、表单和审批卡片 | 适合需要用户决策的长任务 |
| 任务清单 | TodoWrite、TodoCreate、TodoGet、TodoUpdate、TodoList | 可跟踪中小型任务和依赖关系 |

### 3.2 修改审核与恢复

- 每轮 Pi 提示和直接 Bash 命令可以生成 Git 检查点。
- 检查点支持查看差异、整批恢复和按文件恢复，并在外部修改时阻止危险覆盖。
- 文件面板支持暂存、取消暂存、放弃修改、提交、Unified Diff 和 Split Diff。
- Worktree 支持创建、查看、审核、快进合并和安全清理。
- GitHub PR 状态、CI 检查和草稿 PR 创建已经接入，适合个人维护公开仓库。

个人用户最常用的“改动后检查、发现问题、局部恢复”路径已经比单纯终端操作更完整。

### 3.3 规则、记忆和扩展

- `AGENTS.md`、`AGENTS.override.md`、`CLAUDE.md`、`CLAUDE.local.md` 和用户记忆可以参与上下文。
- `.claude/rules` 和 `.pi/rules` 支持路径匹配与 Markdown `@import`。
- `/memory`、`/context`、`/status`、`/compact [指令]` 和自动压缩设置已经有界面入口。
- Claude 兼容 Hooks 已支持 `PreToolUse`、`PostToolUse`、`UserPromptSubmit`、`Stop`、`SessionStart`、`Notification` 等事件，以及 command 和 HTTP handler。
- `/skills` 支持查看、新建和调用 Skills，并尊重 `disable-model-invocation`。
- `.claude/agents` 和 `.pi/agents` 支持提示词、工具、模型、思考强度、权限、Skills、Memory、隔离、后台和作用域 Hooks。

这些能力足以让个人用户维护一套自己的编码规则和自动检查流程。

### 3.4 多模型与 Agent

- 支持 Anthropic、OpenAI、Google、OpenRouter、DeepSeek 和自定义协议。
- API Key 使用 Electron `safeStorage` 保存，不返回渲染进程，也不放在启动参数中。
- 支持 Pi 子 Agent、Explore、Plan、fork、后台任务、审批、续写和结果回传。
- 支持 Agent Teams、Workflow、Cron、Monitor、Todo 和 `/batch` 式并行任务。
- 支持本机 Codex、Claude Code、Kimi Code 和 Antigravity CLI 执行器，保留原生会话、审批、Worktree 和继续执行能力。

多模型和本机外部 Agent 是 Pi Desktop 面向个人用户的核心差异化能力，应继续保持。

## 4. 个人用户仍然需要的能力

### P0：先解决可靠性和安全边界

#### 4.1 活动任务的跨重启接管

当前应用退出会清理本地进程，活动任务会记录为 interrupted。用户可以查看历史并发送新指令继续，但模型轮次、审批等待和命令进程不会原地恢复。

个人用户经常把测试、迁移和长时间分析交给后台任务。推荐增加轻量 supervisor。

- 把任务状态、原生会话 ID、待审批请求和工作目录持久化。
- 应用重新打开后提供“继续这一轮”和“从最后状态重新启动”两个明确操作。
- 保留当前已有的“不自动重跑付费请求”原则。
- 任务抽屉显示中断原因、最后输出和可继续条件。

这项能力比云会话和跨设备接管更适合个人版。

#### 4.2 统一显示执行边界

macOS Seatbelt 已可以保护 Agent Bash 和 Monitor 命令，也会屏蔽常见凭据目录。当前交互 PTY、MCP、Hooks、Pi 扩展、SSH 和外部 Agent 使用各自的进程边界。

个人用户需要在每个入口看到清晰状态。

- 在 PTY、MCP、Hooks、外部 Agent 面板显示“受 Seatbelt 保护”“使用执行器自身沙箱”或“未隔离”。
- 允许用户为交互 PTY 选择项目沙箱和离线沙箱。
- 创建 MCP 和外部 Agent 时显示其工作目录、网络能力和认证来源。
- 在权限弹窗中区分“模型工具授权”和“操作系统隔离”。

#### 4.3 任务和测试的可诊断性

完整回归已经通过，但真实第三方模型、真实 MCP 服务和语言服务器的错误仍需要用户从日志中判断。个人版需要低成本诊断。

- 增加“复制诊断报告”入口，包含版本、平台、Pi 引擎、执行器能力和最近一次失败阶段。
- 对模型连接、MCP 启动、语言服务器和 PTY 启动分别显示可操作的错误原因。
- 在设置中显示运行时版本和配置目录。

### P1：降低每天的操作摩擦

#### 4.4 模型连接、fallback 和成本

当前首次使用需要 API Key 或已有 Pi 登录配置。个人用户更需要简单可靠的连接管理。

- 连接向导能够检查 API Key、OAuth 配置、模型 ID 和协议。
- 当前模型过载或不可用时，按用户设置切换 fallback model。
- 用量面板显示本轮、当天和按服务商的 Token 与费用。
- 允许为“快速问答、编码、复杂重构”保存个人模型预设。

OAuth、SSO 和企业网关属于可选扩展。个人版优先解决连接成功率和故障切换。

#### 4.5 Claude 配置兼容

当前项目配置已经兼容大量 `.claude` 规则、Agents、Skills 和 Hooks。MCP 管理主要使用 `~/.pi/agent/mcp.json` 与 `.pi/mcp.json`，个人用户从 Claude Code 项目迁移时仍需手动调整。

- 读取常见的项目 `.mcp.json`。
- 保留未知 MCP 字段和 OAuth 配置，避免客户端保存时丢失信息。
- 在 `/mcp` 中显示连接状态、最近错误、工具数量和重载结果。
- 对无法转换的权限规则和 Hooks 显示明确的迁移报告。

#### 4.6 个人快捷键与草稿

当前有会话搜索、命令面板、侧问、桌面通知和固定快捷键。个人用户长期使用时还需要更稳定的输入状态。

- 保存每个会话的输入草稿，应用重启后继续显示。
- 支持少量常用快捷键自定义，并提供 Vim 输入模式作为可选项。
- 允许保存“模型、思考强度、权限模式、沙箱”组合为个人预设。
- 提供紧凑布局和更宽的代码审查布局。

#### 4.7 个人质量工作流

Claude Code 的 `/code-review`、`/security-review`、`/simplify` 等命令适合直接复用。个人版可以优先做本地流程。

- 提供代码审查 Skill 模板，读取当前 Diff 并按严重性输出问题。
- 提供测试、格式化、类型检查和安全扫描的项目级快捷入口。
- 让 Hooks 在编辑后或提交前执行这些检查，并在任务卡片中显示结果。
- 将失败检查关联到具体文件和行号。

### P2：个人用户可选能力

- 自动更新和更顺滑的 macOS 安装升级。
- WebSearch 或可配置的本地搜索服务。
- 更完整的 MCP Resources 和 Prompts 浏览。
- 多面板拖拽布局。
- Linux 和 Windows 的实机验收。
- 对常用个人插件和 Pi packages 提供安装管理。

## 5. 个人用户可以暂缓的能力

以下能力不会阻塞个人用户完成本地编码闭环。

| 能力 | 当前判断 | 处理方式 |
| --- | --- | --- |
| 企业 SSO、托管策略、审计和网关 | 组织管理能力 | 个人版暂缓 |
| 云会话、Remote Control、Mobile、Dispatch | 需要云端服务和跨设备基础设施 | 个人版暂缓 |
| Agent Teams 的大规模跨会话编排 | 适合团队和批量工程 | 保留当前 Teams、Workflow 和 `/batch`，观察真实使用需求 |
| 官方插件市场 | 生态分发能力 | 先保持 `.claude`、`.pi` Skills、Agents 和 Hooks 兼容 |
| Chrome 操控、Computer Use、语音 | 外部平台依赖较强 | 个人版暂缓 |
| 完整企业级多平台安装器 | 发布规模能力 | 先保证 macOS 打包和签名流程 |

暂缓这些方向可以把资源集中在本地任务可恢复、权限边界清晰和模型连接稳定上。

## 7. 推荐路线图

### 第一阶段：个人用户可靠性

1. 活动任务持久化与跨重启继续。
2. 统一展示 Bash、PTY、MCP、Hooks 和外部 Agent 的隔离状态。
3. 模型连接诊断、fallback model 和成本摘要。
4. 更新过时文档，保持源码、README、后端接口和外部 Agent 契约一致。
5. 增加个人项目的诊断报告和失败阶段提示。

### 第二阶段：个人效率

1. `.mcp.json` 兼容和 MCP 健康状态。
2. 会话草稿持久化、模型预设和快捷键自定义。
3. 代码审查、测试、格式化和安全检查的内置 Skills。
4. WebSearch 或可配置的本地搜索。
5. 自动更新和 macOS 安装体验。

### 第三阶段：按真实需求扩展

1. 更丰富的 MCP Resources、Prompts 和工具暴露管理。
2. Linux 和 Windows 的终端、沙箱与打包验收。
3. 常用 Pi packages 和个人插件的安装管理。
4. 更复杂的批量 Agent 编排。
5. 云端或跨设备能力，前提是个人用户确实需要长期接管任务。

## 8. 文档维护规则

- 能力状态以当前源码、`npm run verify:client` 和后端回归为准。
- 新增能力完成后，同步更新 README 的“已接入”和本文件的能力矩阵。
- 后端接口已经有前端入口时，接口文档应写明实际入口，避免继续标注为“未接入”。
- 需要真实第三方账号、OAuth、语言服务器或特定操作系统的能力，应在文档中单独标注验证范围。
- 评估优先回答个人用户能否稳定完成任务，再记录与 Claude Code 的协议差异。

## 9. 个人版最后判断

Pi Desktop 已经可以作为个人用户的本地编码工作台使用。它的优势是多模型、本机多 Agent、GUI Git 工作流、检查点和中文交互。当前最重要的改进是让长任务可恢复、让各执行入口的安全边界可见、让模型连接具备故障切换，并持续降低个人配置成本。

Claude Code 的企业治理、云端协作和跨设备能力不应继续主导个人版的差距评分。个人版应围绕“打开项目、理解代码、完成修改、运行验证、审查差异、发现问题后安全恢复”这条闭环持续优化。
